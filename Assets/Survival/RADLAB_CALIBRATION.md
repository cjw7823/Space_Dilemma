# RadLab 평균 선량률과 8분 SPE

2026-11-15 사용자 결정: 48 게임시간을 실제 플레이 10분으로 압축하고, 8분에 SPE를 시작한다. 위험 기준은 600 game mSv로 유지한다. 계속 실외에 있으면 이벤트 후 약 2분 안에 제한치에 도달하도록 k를 역산했다. 일시정지 시간은 플레이 시간에 포함하지 않는다.

SampleScene의 메인 화면에서 **게임 시작**을 누르면 HUD Canvas의 `Radiation Briefing Overlay`가 게임을 일시정지한 상태에서 열린다. 전후 관측 평균, 실제 플레이 초당 실외 증가율, SPE 시작 시각, 차폐와 종료 기준을 세션 설정에서 읽고 NASA RadLab·DONKI 출처를 표시한다. 한글·영문은 게임 설정을 따르며 **임무 시작**으로 닫으면 시간과 피폭량이 움직인다.

## 적용값

`Assets/Scenario/Scenario Rules.asset`의 Inspector에서 **시간과 SPE**, **방사선과 차폐**를 편집한다. 수정값은 다음 Play부터 적용된다.

| 항목 | 값 |
| --- | --- |
| 실제 1초당 게임시간 | 0.08 게임시간 |
| 제한 시간 | 48 게임시간 = 실제 600초 |
| SPE 시작 | 38.4 게임시간 = 실제 480초 |
| SPE 지속시간 | 0: 임무 종료까지 |
| RadLab 전후 평균 사용 | 활성 |
| 게임 환산계수 k | 570 |
| 위험 기준 | 600 game mSv |
| 이벤트 전 실측 평균 | 11.466440972222221 μGy/h |
| 이벤트 후 실측 평균 | 65.12366319444443 μGy/h |

두 평균은 DONKI 기준 시각 **2022-08-27 11:12 UTC**의 전후 각각 48시간에 대한 CRaTER-D1D2 흡수선량률 분석 결과다. 출처 파일은 `MoonData/Radiation_Analyzer/output_unity_k570/analysis_summary.json`이며 원본 입력은 같은 도구 폴더의 `data/radlab_moon_observations.csv`다. 실시간 우주기상이나 게임 배경 날짜의 실제 폭풍 예보가 아니다.

## 환산과 역산

게임시간당 선량률 = 관측 평균(μGy/h) × k / 1000.

실제 플레이 초당 증가량 = 게임시간당 선량률 × 0.08.

| 구간 | game mSv/게임시간 | game mSv/플레이 초 |
| --- | --- | --- |
| SPE 전 | 6.5358713542 | 0.5228697083 |
| SPE 후 | 37.1204880208 | 2.9696390417 |

전후 비율 **5.679501배**를 유지한다. k는 두 구간을 같은 비율로 확대하며 이벤트 발생 시각을 바꾸지 않는다. 이벤트 시각은 `speStartHour / gameHoursPerSecond`로 따로 결정된다.

시작 선량 0, 처음부터 끝까지 실외·차폐 없음인 경우의 10분 누적량은 다음과 같다.

`D(600초) = k × (11.466440972222221 × 38.4 + 65.12366319444443 × 9.6) / 1000`

이를 600으로 놓으면 **k = 563.1167007743**이다. 마지막 프레임의 정상 종료 경계보다 먼저 제한치에 도달하도록 **k=570**을 적용했다. 이벤트 순간 누적량은 약 **250.97746**, 차단하지 않았을 때 10분 누적량은 약 **607.334145**다. 실제 종료는 **597.5303초(9분 57.53초)**, 이벤트 후 **117.5303초**에 600 도달이다.

실내 수동 차폐와 능동 차폐 규칙은 기존 값을 유지한다. 따라서 실내로 대피하거나 시작 선량/시각을 바꾸면 종료 시각도 달라진다. 이 보정은 모든 플레이를 강제 실패시키는 타이머가 아니다.

게임 mSv는 임의의 밸런스 단위다. 궤도 검출기의 흡수선량률을 인체 유효선량이나 달 표면 실측 피폭량으로 환산한 것이 아니다. 600도 게임 종료 규칙으로 사용한다. 출처와 원래 단위의 한계는 분석 도구 README를 따른다.

## 분석 도구

Python 계산 로직은 수정하지 않았다. 기존 `--game-gain` 옵션으로 새 출력을 만들었고 k=200 원본 예시는 보존했다. 도구 폴더에서 다음 명령으로 재생성할 수 있다.

```powershell
python moon_sep_windows.py analyze --input data/radlab_moon_observations.csv --sep-time 2022-08-27T11:12:00Z --game-gain 570 --out output_unity_k570
```

도구가 내보내는 `game_48h_sep_at_24h_1min.csv`의 24시간 배치는 그대로다. **현재 Unity는 그 시계열을 읽지 않고 분석 요약의 전후 평균을 두 상수 구간으로 사용한다.** 따라서 도구의 시계열 적분 총량과 Unity의 38.4/9.6시간 평균 구간 적분 총량은 다르다. 1분 CSV 자체가 38.4시간 이벤트로 변경된 것으로 해석하면 안 된다.

`Tools > Survival > Apply RadLab Average Calibration`은 새 요약에서 평균과 k를 읽고 위 시간/기준값을 다시 적용하는 선택적 설정 메뉴다. 직접 바꾼 해당 설정값은 덮어쓰므로 단순 검증 목적으로 누르지 않는다. 검증 메뉴는 `Validate RadLab Calibration`, 결과는 `QA/RadLabCalibration`이다.
