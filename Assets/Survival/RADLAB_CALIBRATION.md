# RadLab 자료와 이벤트 시점 피폭 보정

2026-11-15 사용자 결정: 48 게임시간을 실제 10분으로 압축하고, 실제 8분에 SPE를 시작한다. SPE 순간의 누적 피폭량을 확인해 남은 피폭 한도를 남은 시간에 채우는 실외 선량률을 **한 번 계산**한다. 종료 전에 확실히 위험 기준에 도달하도록 기본 여유 배율은 **1.1**이다. 이후 실내나 능동 차폐로 줄인 피폭량은 보존하며 선량률을 재계산하지 않는다. 일시정지 시간은 제외한다.

## 설정과 계산

`Assets/Scenario/Scenario Rules.asset`의 **방사선과 차폐**에서 `SPE 시작 시 남은 피폭 한도 보정`과 `SPE 잔여량 보정 여유 배율`을 편집한다. 다음 Play부터 적용된다.

| 항목 | 현재 값 |
| --- | --- |
| 임무 시간 / 실제 1초당 게임시간 | 48시간 / 0.08시간 |
| SPE 시작 / 지속시간 | 38.4시간 / 0이면 종료까지 |
| 위험 기준 | 600 game mSv = 피폭 게이지 100% |
| RadLab 기준 환산계수 k | 570 |
| SPE 잔여량 보정 | 활성 |
| 보정 여유 배율 | 1.1 |
| 실내 수동 차폐 투과율 / 능동 차폐 최대 추가 감소율 | 35% / 80% |

SPE 전에는 `관측 전 평균 × k / 1000`을 사용한다. 현재 **6.5358713542 game mSv/게임시간**, 실제 플레이 1초당 **0.5228697083**이다.

SPE가 시작되는 순간 게임시간을 `t`, 당시 누적 선량을 `D`, 종료 시간을 `T`, 위험 기준을 `L`, 여유 배율을 `M`이라고 하면 다음과 같다.

```text
실외 SPE 선량률 R = max(1, M) × max(0, L − D) / (T − t)
실제 플레이 초당 증가량 = R × 실제 1초당 게임시간
```

현재 설정에서 이벤트 이후 계속 실외·무차폐이면 이벤트 전 실내 체류 시간과 관계없이 **120 / 1.1 = 약 109.09초** 뒤에 600에 도달한다. 전체 플레이 **9분 49.09초**, 게임시간 **약 47.12727시간**이다. 이미 시작 전에 위험 기준에 도달한 경우에는 기존 사망 규칙을 따른다. 배율 1은 48시간 경계에서 100%가 되며 경계가 겹치면 사망을 우선한다.

예를 들어 SPE 때 누적량이 0이면 실외 증가율은 약 **68.75 game mSv/게임시간**, 처음 8분간 실내(수동 차폐만)에 있었다면 누적량 약 **87.84211**에서 실외 증가율 약 **58.68476**으로 고정된다. 이미 쌓인 선량을 초기화하거나 이벤트 순간 게이지를 올리지 않는다.

이벤트 이후 실내에 있으면 고정된 R의 35%를 받고, 능동 차폐가 80%를 추가로 줄이면 R의 7%를 받는다. 밖으로 돌아와도 최초 R을 사용한다. 대피한 시간만큼 피폭이 줄어들므로 모든 플레이가 강제로 실패하는 타이머가 아니다. 회피 선량 통계도 이 실제 R을 기준으로 계산한다.

SPE 도중의 사용자 지정 시각으로 시작하면 그 시작 시각·선량·남은 시간을 기준으로 한 번 계산한다. SPE를 임무 중에 끝내도록 설정하면 끝난 뒤 평상시 선량률로 돌아가므로 위의 종료 전 도달 조건은 적용되지 않는다. SPE가 없으면 보정하지 않는다. 이 옵션을 끄면 기존 관측 평균 또는 수동 선량률의 두 구간 계산을 사용한다.

## NASA 자료와 게임 보정의 구분

CRaTER-D1D2 관측 평균은 DONKI 기준 **2022-08-27 11:12 UTC** 전후 각각 48시간의 **11.466440972222221 / 65.12366319444443 μGy/h**다. 관측 전후 비율 **5.679501배**는 원자료의 특징이다. 잔여량 보정에서는 SPE 선량률이 플레이어 상태로 결정되므로 게임 선량률 비율까지 이 값을 유지하지 않는다. SPE 전 기본 환산계수는 k=570이다.

분석 요약은 `MoonData/Radiation_Analyzer/output_unity_k570/analysis_summary.json`, 원본 입력은 `data/radlab_moon_observations.csv`다. Python의 기존 고정 k 분석은 보존하며 이벤트 시점 보정은 Unity의 `SurvivalRun`에서 계산한다. 기존 도구 출력 `game_48h_sep_at_24h_1min.csv`는 현재 Unity가 읽지 않는다.

```powershell
python moon_sep_windows.py analyze --input data/radlab_moon_observations.csv --sep-time 2022-08-27T11:12:00Z --game-gain 570 --out output_unity_k570
```

game mSv는 게임 밸런스 단위다. 궤도 검출기의 흡수선량률을 달 표면 실측 인체 선량으로 환산한 것이 아니다. 하늘의 2024년 날짜와 방사선의 2022년 관측은 별도 자료다.

메인 화면의 **게임 시작** 다음에 열리는 씬의 `Radiation Briefing Overlay`도 관측값, k, 잔여량 계산과 여유 배율을 한글·영문으로 표시한다. `Tools > Survival > Apply RadLab Average Calibration`은 원본 평균·k와 현재 보정 옵션/1.1 배율·시간을 다시 적용하므로 수동 설정을 보존하려면 실행하지 않는다. 검증 메뉴는 `Validate RadLab Calibration`, 최신 결과는 `QA/RadLabCalibration/RemainingDose`다. 상위 QA 폴더의 k=570 고정 모드 결과는 이전 검증 기록이다.
