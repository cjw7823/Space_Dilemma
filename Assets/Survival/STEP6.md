# STEP 6 — 최종 평가와 결과 UI

## 사용과 씬 구성

48시간을 마치거나 누적 피폭량이 위험 기준에 도달하면 플레이를 멈추고 최종 결과를 자동 표시한다. 생존 여부와 연구 점수는 별도로 평가한다. 사망했다고 이미 얻은 연구 점수를 0으로 바꾸지 않는다.

Hierarchy의 `Survival Session/FinalEvaluation`이 종료 이벤트를 받고, `Space HUD/HUD Canvas/Final Result Overlay/Result Window`에 저장한 UI를 갱신한다. 실행 중 오브젝트나 UI를 생성하지 않는다. 편집할 때 Final Result Overlay를 켜면 창·텍스트·버튼·진행 막대의 배치를 수정할 수 있다. 기본 상태는 OFF로 유지한다. 텍스트와 막대는 실행 중 최종 데이터 및 언어 설정으로 갱신된다.

결과 화면의 설정 버튼은 기존 언어·COM 설정 화면으로 연결된다. 설정/ESC 메뉴에서 돌아와도 시간은 정지하며 동일한 결과를 보여준다. 게임 종료는 빌드에서 애플리케이션을 종료하고 Editor에서는 Play를 멈춘다. 재시작·저장·파일 내보내기 기능은 이번 결과 UI에 추가하지 않았다.

## 표시 항목

- 생존 / 사망과 실제 종료 경과 시간. 조기 사망은 48시간으로 덮어쓰지 않는다.
- 최종 누적 피폭량.
- 실내 SPE 보호 시간 / 실내 SPE 체류 시간.
- 실내 SPE 전체 시간에 대한 시간 가중 평균 감소율.
- 같은 실내 수동 차폐만 있었을 때와 비교해 능동차폐로 줄인 피폭량.
- 시료 채취·보존, 측정장비, 식물 재배 연구 달성률과 각각의 막대.
- 세 미션을 종합한 전체 연구 달성률.
- 보관 시료 중 현재 유효 품질인 수. 이는 현재 전원 ON 개수와 다른 값이다.

차폐 운용 기록은 매 적분 구간에서 실제 사용한 시간만 더한다. SPE 경계 전의 시간을 보호 시간으로 세지 않고, 조기 사망 시 요청한 전체 시간 대신 위험 기준에 도달할 때까지의 구간만 기록한다. 차폐 출력을 마지막에 올렸다고 전체 시간의 감소율이 올라가지 않는다. 실외의 켜진 실내 차폐에는 보호 실적을 주지 않는다. 평균의 분모인 실내 SPE 시간이 0이면 평균은 0으로 표시한다.

## 점수 설정

`Assets/Survival/Evaluation Rules.asset`에서 Samples Weight / Instruments Weight / Plants Weight를 조절한다. 기본은 1 / 1 / 1로 동일 가중 평균이다.

`전체 연구 달성률 = Σ(미션 달성률 × 가중치) / Σ가중치`

가중치 0인 미션은 종합 점수에서 제외된다. 모두 0이면 동일 가중 평균으로 처리한다. 미션별 결과는 그대로 표시한다. 실행 시작 때 가중치를 복사하므로 실행 중 정의 에셋을 수정하지 않는다. 결과는 종료 시점에 한 번만 캡처하며 이후 전력·시간·정의·언어 변경으로 다시 계산하지 않는다.

미션별 데이터율·상한·목표는 기존 Research Data Rules, 방사선/종료 기준은 Survival Rules, 전력은 Base Power Rules, 효율과 품질은 STEP 5 설정을 사용한다. 결과 시스템이 별도의 자원 계산이나 승패 기준을 만들지 않는다.

## 코드와 데이터 흐름

- `SurvivalRun`: 기존 선량 적분에 실내 SPE 시간·보호 시간·감소율 적분·회피 선량 기록을 추가했다. 실제 선량 계산에서 사용한 투과율로 기록한다.
- `EvaluationRules`: 세 미션의 종합 점수 가중치 정의.
- `FinalReport`: 종료된 SurvivalRun 및 고정된 ResearchLedger에서 만드는 변경 불가능한 결과 스냅샷.
- `FinalEvaluation`: `SurvivalRun.Ended → ResearchLedger.Finish → FinalReport` 순으로 한 번 확정하고, 씬 UI와 기존 설정 메뉴를 연결한다. 종료 입력 차단과 시간 정지는 기존 SurvivalSession이 담당한다.
- `Editor/FinalStepChecks`: 무수행·부분 수행·SPE 이전 전체 달성·차폐 우선·차단 순서 변화·실외 잔류·조기 사망·가중치·중복 종료·두 언어의 실제 결과 UI 검사.

## 검증과 한계

`Tools > Space HUD`의 Run Result Survival Validation / Run Result Death Validation은 결과에 집중한 검사다. Run Play Validation은 이전 단계 회귀와 종료 평가 연결을 확인한다. 검사에서 실제 COM을 열지 않으며 Unity 내부의 실제 입력과 가상 입력을 분리한 뒤 복원한다. 실행한 결과는 `QA/ResultStep6/VALIDATION.md`를 따른다.

STEP 1~6의 계획된 기능 구현과 자동 검사 완료를 게임 전체의 출시 검증과 구분한다. 방사선 위험 기준·효율·품질·데이터율·요구 전력은 여전히 임시 게임 수치다. 현재 기본 수치가 모든 선택에서 긴박한 딜레마를 만들도록 조율된 것은 아니다. 독립 실행 빌드·실물 Arduino/COM·실제 보행 전체·학생 체험·난이도와 교육 효과는 별도 검증이 필요하다. NASA 관측 자료와 게임 가정을 혼동하지 않는다.

## 종료 안내 문구 (2026-11-15)

정상 종료 결과창은 '지구 무사 컴백! 축하합니다'와 '당신 덕분에 소중한 연구 자료와 자원을 얻게 되었어요. / 정말 감사합니다!'를 표시한다. 전체 연구 달성률의 기존 가중 계산값을 '임무 완수율: … %'로 표시한다. 피폭 제한치에 도달한 결과창은 '게임 오버'와 '방사선 피폭량이 제한치에 도달했습니다. / 안전 수칙 위반으로 게임 오버되었습니다.'를 표시한다. 한글·영문 전환을 지원하며 기존 종료 조건과 점수 계산은 유지한다.
